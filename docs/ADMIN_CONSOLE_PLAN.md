# 後台功能補全計畫

> 狀態：定案（2026-08-30，使用者授權「依合理的後台功能陸續實作」）。基底：schema 正規化後的結構（bosses/question_hints）。
> 原則：全部走既有 `Admin::BaseController` 伺服器端驗證；後台是營運工具不是展示重點，沿用 `docs/UI_STYLE_GUIDE.md` 的明亮後台配方、簡潔為上；破壞性操作要二次確認與範圍限制。

## 功能清單（依實作順序）

### A1 後台導覽骨架
- admin layout 區塊：頂欄（現有）＋側欄導覽（Dashboard／隊伍／題目／兌獎序號／遊戲序號）；現有頁面掛進導覽。

### A2 Dashboard 強化（現有 3 卡 → 營運總覽）
- 既有統計保留；新增：各題完成隊數的進度分布（橫條）、進行中戰鬥數、已結算隊伍數、兌獎序號池餘量（正式/測試各自）。
- 純查詢彙總，不引入圖表庫（Tailwind 橫條即可）。

### A3 隊伍管理
- `admin/teams#index`：分頁列表（序號、隊名、人數、test_mode、解題進度 n/11、建立時間），支援序號/隊名搜尋與 test_mode 篩選。
- `#show`：隊員清單（角色/職業/email/聯絡資訊遮罩顯示——手機以 09**-***-*** 形式）、各題 attempt（耗時/提示數/完成時間）、Boss 戰紀錄、分數明細、兌獎序號配發狀態。
- 危險操作：**僅限 `test_mode: true` 隊伍**可刪除（連同關聯資料），刪除鈕帶 turbo_confirm；正式隊伍不提供刪除（營運資料保護）。

### A4 題目管理
- `admin/questions#index`：11 題列表（編號/標題/題型/難度/魔王/提示數）。
- `#edit/#update`：標題、內容、難度、解說、提示（子表的新增/修改/刪除/排序——nested form 或獨立小表單皆可，取簡單）、Boss 參數（hp/時限）、**答案重設**（輸入明文→伺服器轉 digest 儲存，永不回顯明文；留空＝不變更）。
- 不提供 create/destroy（11 題是遊戲結構，固定）。

### A5 兌獎序號管理
- `admin/reward_codes#index`：池狀態統計（未配發/已配發、正式/測試）、列表（code、test_mode、配發對象 email 遮罩、claimed_at）、依 email 查詢。
- `#create`：批次產生兌獎序號（數量參數化、test_mode 選項、insert_all、撞號重生成）——補齊現況「只有隊伍序號產生器」的缺口。

### 範圍外（本輪不做）
- 玩家個別編輯/刪除、操作稽核日誌、後台多帳號角色權限、匯出報表。

## 測試要求
- 每個 controller：未登入 302、登入後 200、危險操作的範圍限制（刪正式隊伍被拒、答案重設 digest 正確且不回顯）。
- 隊伍刪除的關聯清理完整（attempts/battles/readies/scores 不留孤兒）。
- M0 黃金值與全部既有測試不退步。
